# 暱稱＋IP 登記與來源 IP 流量統計：整合規格（未部署）

## 註冊模式
- 原有 Supabase Auth 電子郵件會員保留，登入、忘記密碼、成績及救援紀錄不遷移。
- 新增管理員設定「允許新的電子郵件註冊」，正式停用必須在 Supabase Auth 伺服器端落實，不能僅隱藏按鈕。此分支的資料庫開關目前只儲存設定，**尚未封鎖 Auth signup API**。
- IP 不等於一人：NAT、校園或公司網路會共用 IP；手機網路、VPN 和動態 IP 會改變位址。因此「暱稱＋IP」只能用於訪客登記／試玩限制，不能取代已驗證的會員身分或授權。
- 管理員、會員教材、排行榜、救援點數仍須有效的 Supabase Auth 憑證。
- 若要無電子郵件的正式會員，須另外建置可復原的驗證方式（例如 passkey），並測試授權與帳號接續；不得把 IP 當成登入憑證。

## IP 點擊紀錄
- 目前每日流量統計僅存聚合數值，不能還原過去訪客 IP。
- 新紀錄僅由伺服器讀取可信的邊緣網路 IP；不得採信瀏覽器傳來的 IP 或任意 X-Forwarded-For。
- 最小欄位：來源 IP、事件時間、事件類型（頁面開啟或點擊）、頁面、來源分類、匿名化的控制項名稱。**不得蒐集表單值、密碼、URL 查詢字串與題目答案。**
- 管理員登入後才能檢視原始 IP；前台不能查詢。需限制查詢次數、防止濫用和防護 RLS。
- IP 屬個人資料，預設保存 30 天且定期刪除；網站需揭露蒐集目的、保存期間與聯絡方式。
- 頁面開啟與點擊數不可直接視為實際訪客人數；機器人、預取與多次點擊應另行註明。

## 上線門檻
1. 在獨立的測試 Supabase 專案部署 SQL 與 Edge Function，測試匿名與管理員的 RLS／授權。
2. 真正阻擋新電子郵件註冊，同時確認舊會員仍可登入與重設密碼。
3. 驗證伺服器來源 IP，不接受使用者自填 IP；測試共用 IP、IP 更換與並行登記。
4. 驗證點擊計次、去重、限流、30 天清理、管理員明細及無權限拒絕。
5. 測試通過才可合併主分支及更新 GitHub Pages。正式資料庫先不動。
